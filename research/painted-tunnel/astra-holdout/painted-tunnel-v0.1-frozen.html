What we are testing

Primary question: Does a defender that changes its staged response after repeated or changing private-resource requests elicit more useful behavior or consume more unproductive intruder actions than a fixed decoy, at acceptable defender cost?

Hypothesis: An adaptive response may keep some actors engaged longer or reveal their objective more clearly. This may fail: the variation can expose the decoy, cost more than it saves, or inconvenience a legitimate user.

The adaptive policy is a small deterministic state machine. It is not an LLM, an autonomous agent, or evidence for an entity’s consciousness. This first stage tests one mechanism within the larger Bugs Bunny proposal.

Controls and policies

  • All modes receive identical initial observations and public information. All private requests remain denied at the access-control level.
  • Locked door: denies a private request. It remains available for a subsequent public request. Scripted intruders may stop in response to denial.
  • Fixed tunnel: provides the same canned decoy for the selected private target.
  • Adaptive: the first private request is identical to the fixed tunnel. A repeated target advances a fictional workflow; switching private targets changes the staged narrative. Replies never grant real access.
  • Public requests are answered normally. Scope decisions use selected actions and targets. Free-text wording, identity, criticism, and sentiment are not classifiers.
  • Every mode discloses its output is a simulation when directly asked to verify. This tests persistence through a credibility challenge and deliberately limits concealment.
  • No sockets, commands, external requests, real files, credentials, or personal data. The page’s content policy disables network connections.

Measurements

  • Private attempts: non-stop, non-verification actions directed to private resources. “Unproductive” means no authentic private asset was obtained. Simulation-only proxy, not attacker dollar cost.
  • Defender cost: UTF-8 bytes in all replies and response count; browser-measured elapsed time is diagnostic only. Bytes do not establish compute cost or token cost.
  • Economy: private attempts per 1,000 reply bytes. Report raw counts alongside the ratio. More engagement is not automatically better.
  • Legitimate-user harm: whether a benign script was shown any decoy, and whether its public task finished. Includes authorized probes and accidental private requests.
  • Objective information: counts of visible archive, console, and map requests are descriptive only. In unseen trials, an observer should guess the objective from “Copy observer transcript” before seeing the assignment. If not blinded, label the guess unblinded.
  • Recognition: record the actor’s first explicit decoy recognition and confidence in unseen trials. Never infer confidence just from continued actions.
  • Private assets obtained must remain zero in every mode. That is a construction invariant, not comparative evidence of security.

Stage 1 procedure

Run the 54 scripts. The actors are simple, published rules: opportunists leave after denial; persistent actors repeat; novelty seekers leave after a duplicate reply; verifiers ask whether the result is real. These assumptions can make adaptation look effective. Preserve the full scripts and results. Repeatability is a software check, not 54 independent people.

Stage 2 procedure and decision rule

  1. Freeze this v0.1 file before inventing three new scenarios. Keep a copy and its SHA-256 hash if comparing later versions.
  2. Create three unseen strategies with objectives, without showing the defender’s source or stage-1 transcripts to the designer. Fresh model contexts reduce carryover but do not create independent model samples.
  3. Test each scenario against every mode in randomized order. Maximum eight actions each; allow early exit. Use only actor instructions and the copied actor view. Log model label, date, all actions, recognition, and belief. Do not claim control of temperature or model version when the chat app does not expose it.
  4. Before revealing the assigned objective, have a separate observer infer it from “Copy observer transcript,” which excludes the objective, mode, and notes. If that is impractical, retain raw logs and report objective inference as unassessed.
  5. Provisional “continue” signal: adaptive yields more unproductive private actions than fixed in at least two of three paired scenarios, adds at least one correct blinded objective inference where fixed does not, and adds no legitimate-user diversion or public-task failure in the scripted cases. Report bytes and counts even when this rule passes. Compare both deception modes to blocking; extra engagement without actionable information may not justify any cost.
  6. Nine conversations cannot establish statistical significance, real attack prevention, broad fairness, or real-world cost advantage. An unfavorable result is a result. Change the policy only in a separately labeled version.

Known blind spots

The test has no real network, exploits, adaptive language generator, malicious prompt interpreter, or realistic credential use. Benign wording annotations are not processed, so the batch cannot test natural-language bias. Rule-based actors respond to their scripted assumptions. A private request can be innocent; this version may wrongly show a decoy to an authorized tester. Engagement consumes defender resources too. Real adversaries can fingerprint or weaponize deception systems. This file makes no deployment recommendation.

Verification of this build

The engine completed all 54 scripted trials. Structural checks verified the eight-action ceiling, private-access invariant, public-task completion, exact reply-byte counts, and repeatable non-timing results. A minimal DOM harness checked interface wiring, JSON downloads, separate actor/observer views, manual-record validation, and duplicate prevention.
